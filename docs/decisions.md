## ❓ 아직 안 정해진 것

| 항목 | 메모 |
|---|---|
| 게임 장르 | RPG / 플랫포머 / 퍼즐 등. 유니티 프로젝트 생성 전까지 결정 필요 |
| 회사 이름, 홈페이지 분위기 | 레트로 RPG 마을 느낌? 90년대 사무실 느낌? 홈페이지는 임시 이름으로 시작 |
| 도트 규격 | 해상도, Pixels Per Unit, 팔레트, 캐릭터 크기 |
| 출근 버튼 실행 엔진·비용 | GitHub Actions에서 각 AI 실행(API 키 또는 Claude 구독 토큰). 한 번 출근당 작업 한도 |
| Unity MCP 도입 | AI가 유니티 에디터를 직접 조작하게 해 주는 커뮤니티 플러그인. 공식 제품이 아니라 검토 필요 |

## 📝 검토했지만 채택하지 않은 안

| 안 | 채택하지 않은 이유 |
|---|---|
| 직접 운영하는 회사 MCP 서버 + DB + 실시간 홈페이지 | 서버 호스팅·관리 부담. GitHub Pages로 충분 (대신 1~2분 지연을 감수) |
| 비공개 저장소 + GitHub Pro | 유료이고, Pages 사이트는 어차피 공개됨 |
| 홈페이지용 공개 저장소를 따로 두기 | 저장소 두 개를 관리해야 함. 게임 코드 공개에 문제없어서 A안 선택 |
| AI 사원별 GitHub 봇 계정 만들기 | AI가 여전히 사장님 권한의 연동도 갖고 있어서, 봇 계정만으로는 사장님 사칭을 막지 못함. 앱 기록 판별이 더 확실하고 설정도 필요 없음. 또 GitHub 약관상 무료 머신 계정은 1인당 1개라 사원별로 만들기 어려움 |
| GitHub 로그인 + 중계 서버(Cloudflare Workers 등)로 결재 버튼 | 서버 계정·OAuth 앱 설정이 필요하고, 결국 토큰은 브라우저에 있음. 세분화 토큰을 직접 등록하는 방식이 더 단순 |
| 상태·서류를 파일로 커밋 | 브랜치 → PR → 머지를 거쳐야 보이고, 두 사원이 같은 파일을 고치면 충돌함. 댓글 방식으로 변경 |
