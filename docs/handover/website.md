## 1. 사장님이 원하는 것 (원문 요약)

> 도트 감성의 홈페이지에서 **AI 사원 두 명이 움직이면서 일하고**, 처리한 서류와 보고 사항을 **서류로 받아보는 것**.
> 홈페이지는 **GitHub Pages**로 보고 싶다.

## 2. 확정된 조건

- **호스팅: GitHub Pages** (저장소 `moooncang/game`, 공개 저장소)
- **서버·DB 없음.** GitHub Issue 댓글이 데이터 원본이고, GitHub Actions가 `feed.json`을 만들어 사이트와 함께 배포합니다.
- 홈페이지는 **읽기 전용**입니다. 지시·결재 같은 쓰기 동작은 GitHub 화면으로 연결합니다.
- 홈페이지는 유니티가 아니라 **웹 기술**로 만듭니다. (게임 본편만 유니티)
- 소스 위치: **`site/`** 폴더

## 3. 화면 요구사항

### 3-1. 도트 사무실 (메인 화면)
- 위에서 내려다보는 시점(탑다운) 또는 측면 시점의 **픽셀 아트 사무실** 한 칸.
- 배치: **Claude 책상**, **GPT 책상**, **회의 테이블**, **사장실 서류함**(또는 사장님 책상).
- 픽셀이 뭉개지지 않게 정수 배율로 확대합니다. (`image-rendering: pixelated`, 캔버스 정수 스케일)
- 휴대폰 화면에서도 사무실 전체가 보여야 합니다.

### 3-2. 사원 캐릭터 2명
- `claude`, `gpt` 각각 구분되는 도트 캐릭터. 머리 위에 이름표.
- **`feed.json`의 `employees.<id>.state`에 따라 행동이 바뀝니다.** 상태별 행동은 [`office/README.md`의 상태 코드 표](../../office/README.md#상태-코드--홈페이지-행동)를 따릅니다.
- 상태가 바뀌면 순간이동하지 말고 **걸어서 이동**합니다.
- 머리 위 말풍선에 `message`를 표시합니다.
- 모르는 상태 코드는 `idle`로 처리합니다.

### 3-3. 서류 제출 연출 ⭐ 핵심
- `feed.json`을 다시 읽었을 때 **새 서류**(`reports`에 처음 보는 `id`)가 있으면:
  1. 작성한 사원이 자리에서 일어나 **서류함으로 걸어가서**
  2. 서류를 넣고 (서류 아이콘이 서류함으로 들어가는 연출)
  3. 다시 원래 하던 행동으로 돌아갑니다.
  4. 서류함에 **새 서류 개수 배지**를 표시합니다.
- "처음 보는 서류"인지는 브라우저 `localStorage`에 확인한 서류 ID를 저장해서 판단합니다. (저장소를 못 쓰는 환경에서도 화면이 깨지지 않게 예외 처리)
- 페이지를 처음 열었을 때 이미 있던 서류는 연출 없이 배지만 표시합니다.

### 3-4. 서류함 (사장님 결재함)
- 서류함을 클릭하면 **도트 종이 느낌의 서류 목록**이 열립니다.
- 목록 항목: 제목, 작성 사원, 종류, 날짜, 결재 상태(도장).
- 서류를 열면 **본문 마크다운을 렌더링**해서 보여 줍니다.
  - ⚠️ 본문은 외부 입력이므로 **HTML을 그대로 넣지 말고 반드시 정화(sanitize)** 하세요. (예: DOMPurify)
- 결재 도장: `approved` = 빨간 "승인" 도장, `rejected` = 파란 "반려" 도장 + 사유, `pending` = 도장 없음.
- 버튼:
  - **[GitHub에서 결재하기]**: 서류의 `url`(해당 Issue 댓글)을 새 탭으로 엽니다.
  - **[관련 PR 보기]**: `pr`이 있으면 `https://github.com/moooncang/game/pull/<pr>`을 엽니다.
- 필터: 전체 / 결재 대기 / 승인 / 반려, 사원별.

### 3-5. 업무 게시판 (보조)
- `tasks` 목록을 화이트보드나 게시판 느낌으로 보여 줍니다. (번호, 제목, 담당, 진행 중/완료)
- **[새 업무 지시]** 버튼: `https://github.com/moooncang/game/issues/new?template=task.yml`을 엽니다.

### 3-6. 기타
- 화면 구석에 "마지막 갱신: N분 전" (`generated_at` 기준) 표시.
- 회사 이름은 아직 정해지지 않았습니다. 임시 이름을 쓰고, 설정 한 곳에서 바꿀 수 있게 해 주세요.

## 4. 데이터 연동

- 홈페이지는 **같은 사이트에 배포된 `feed.json`만** 읽습니다. (브라우저에서 GitHub API를 직접 호출하지 않음 → API 호출 제한 회피)
- **60초마다** `feed.json`을 다시 읽습니다. 캐시를 피하려면 `feed.json?t=<시각>`처럼 요청합니다.
- 시안 단계에서는 [`office/samples/feed.sample.json`](../../office/samples/feed.sample.json)을 사용합니다.
  - 시안에서 서류 제출 연출을 시험할 수 있도록 **데모 모드**(가짜 새 서류를 주기적으로 추가)가 있으면 좋습니다.

## 5. 피드 생성기 + 배포 (GitHub Actions)

`.github/workflows/`에 워크플로를 만들어 주세요. 해야 할 일:

1. **트리거**: `issues`, `issue_comment`, `pull_request`(opened/closed), `push`(`main`의 `site/` 변경), `schedule`(30분마다), `workflow_dispatch`
2. **피드 생성**: 기본 `GITHUB_TOKEN`으로 Issue·댓글·PR을 읽어 `feed.json`을 만듭니다.
   - 해석 규칙: [`office/README.md` §4 해석 규칙](../../office/README.md#해석-규칙-피드-생성기-구현-시)을 반드시 따르세요. 특히 **결재 댓글은 저장소 주인 것만 인정**해야 합니다.
   - 담당자는 Issue 라벨 `담당:claude` / `담당:gpt`에서 추출합니다.
3. **배포**: `site/` 결과물 + `feed.json`을 GitHub Pages에 배포합니다. (`actions/upload-pages-artifact` + `actions/deploy-pages`)
4. 같은 워크플로가 동시에 여러 번 돌지 않도록 `concurrency`를 설정합니다.
5. **비밀 키가 필요 없게** 만들어 주세요. 기본 `GITHUB_TOKEN`으로 충분합니다.

## 6. 기술 제안 (확정 아님, GPT 판단에 맡김)

- 가능하면 **빌드 과정 없이** 동작하는 정적 사이트를 권장합니다. (HTML + JS 모듈, 필요하면 CDN 라이브러리)
  - 2D 연출: Phaser 3 또는 순수 Canvas
  - 마크다운: marked + DOMPurify
- 도트 이미지(사무실 타일, 캐릭터 스프라이트)는 GPT가 직접 생성해서 `site/assets/`에 넣어 주세요.
  - 캐릭터 시트 권장: 16×16 또는 32×32, 4방향 걷기 + 앉아서 타이핑 + 서류 들고 걷기 프레임
- 픽셀 폰트를 쓸 경우 **한글을 지원하는 폰트**인지 확인해 주세요. (예: 둥근모꼴, Galmuri 등 무료 라이선스 확인 필요)

## 7. 완료 기준 (사장님 확인 체크리스트)

- [ ] GitHub Pages 주소에서 도트 사무실이 보인다.
- [ ] 두 사원이 `feed.json` 상태대로 다른 행동을 한다.
- [ ] 상태가 바뀌면 캐릭터가 걸어서 이동한다.
- [ ] 새 서류가 생기면 캐릭터가 서류함에 서류를 넣는 연출이 나온다.
- [ ] 서류함에서 서류를 열어 읽을 수 있고, 결재 도장이 보인다.
- [ ] [GitHub에서 결재하기] 버튼이 해당 댓글로 이동한다.
- [ ] Issue에 상태 댓글을 달면 1~2분 안에 홈페이지에 반영된다.
- [ ] 휴대폰에서도 볼 수 있다.

## 8. 진행 방식

- 사장님이 이 작업용 업무 Issue를 만들면 그 Issue에 상태·서류를 보고해 주세요. (양식: `office/README.md`)
- 권장 순서: ① 시안(샘플 데이터) PR → 사장님 확인 → ② 피드 생성기 + 배포 PR
- 데이터 규격에 바꾸고 싶은 점이 있으면 `claude`에게 Issue로 제안해 주세요. 규격 문서(`office/README.md`)를 먼저 고친 뒤 구현합니다.
- 완료 후 PR 리뷰는 `claude`가 합니다.
