# 업무 데이터 규격 (office)

AI 사원의 **상태 보고**, **업무 보고서(서류)**, 사장님의 **결재**를 남기는 양식입니다.
회사 홈페이지는 이 양식을 해석해서 캐릭터를 움직이고 서류함을 채웁니다. **양식을 정확히 지켜 주세요.**

모든 보고는 **해당 업무 Issue의 댓글**로 남깁니다.
댓글 첫 줄의 HTML 주석 표식(`<!-- office:... -->`)으로 종류를 구분합니다. 이 주석은 GitHub 화면에는 보이지 않습니다.

---

## 1. 상태 보고 (`office:status`)

작업 시작, 작업 종류가 바뀔 때, 작업을 마칠 때 남깁니다.

```markdown
<!-- office:status -->
사원: claude
상태: coding
메시지: 플레이어 이동 스크립트 작성 중
```

| 항목 | 필수 | 값 |
|---|---|---|
| `사원` | ✅ | `claude` 또는 `gpt` |
| `상태` | ✅ | 아래 상태 코드 중 하나 |
| `메시지` | ✅ | 한 줄 설명 (홈페이지 말풍선에 표시, 40자 이내 권장) |

### 상태 코드 → 홈페이지 행동

| 코드 | 의미 | 캐릭터 행동 (권장) |
|---|---|---|
| `offline` | 퇴근 | 자리에 없음 (책상 비어 있음) |
| `idle` | 대기 | 자리에 앉아 쉬거나 사무실을 어슬렁거림 |
| `coding` | 코딩 중 | 자기 책상에서 타이핑 |
| `designing` | 도트 아트·디자인 중 | 책상에서 그림 그리기(펜 태블릿) |
| `writing` | 기획·문서·대사 작성 중 | 책상에서 종이에 쓰기 |
| `reviewing` | 동료 결과물 검토 중 | 동료 책상으로 걸어가서 모니터 보기 |
| `meeting` | 회의·질문 대기 | 회의 테이블로 이동 |
| `blocked` | 막힘, 사장님 도움 필요 | 머리 위에 `!` 표시, 제자리에서 고민 |

> 상태 코드를 새로 추가할 때는 이 표를 먼저 고치고, 홈페이지 담당(`gpt`)에게 알립니다.
> 홈페이지는 모르는 상태 코드를 받으면 `idle`로 처리해야 합니다.

## 2. 업무 보고서 (`office:report`) — "서류"

업무를 끝냈거나, 중간 보고·질문이 필요할 때 남깁니다. 홈페이지에서는 **캐릭터가 사장실 서류함으로 걸어가 서류를 놓는 장면**으로 표시됩니다.

```markdown
<!-- office:report -->
사원: claude
종류: 작업보고
제목: 플레이어 이동 구현 완료
PR: #4

## 한 일
- 방향키/WASD로 8방향 이동 구현
- 대각선 이동 속도 보정

## 사장님 확인 사항
- 유니티 에디터에서 `Scenes/Test` 씬을 열고 플레이해서 이동 속도가 적당한지 봐 주세요.

## 질문
- 달리기 버튼이 필요한가요?
```

| 항목 | 필수 | 값 |
|---|---|---|
| `사원` | ✅ | `claude` 또는 `gpt` |
| `종류` | ✅ | `작업보고` / `중간보고` / `질문` / `리뷰결과` / `기획안` |
| `제목` | ✅ | 서류 제목 (홈페이지 서류 목록에 표시) |
| `PR` | ⬜ | 관련 PR 번호 (`#4`) |
| 본문 | ✅ | 머리 항목 아래 빈 줄 다음부터 끝까지. 마크다운 자유 형식 |

- 머리 항목은 `키: 값` 형식이며 **빈 줄이 나오기 전까지**만 머리 항목으로 읽습니다.
- 서류 번호는 따로 붙이지 않습니다. **댓글 ID**가 서류 번호 역할을 합니다.

---

## 3. 결재 (사장님)

해당 Issue에 아래처럼 댓글을 남깁니다. 결재는 **그 Issue에서 가장 최근에 제출된 서류**에 적용됩니다.

```
/승인
```
```
/반려 이동 속도가 너무 빨라요. 절반으로 줄여 주세요.
```

- 홈페이지는 서류에 `승인`(빨간 도장) / `반려`(파란 도장) / `대기`(도장 없음)를 표시합니다.
- `/반려` 뒤의 문장은 반려 사유로 서류에 함께 표시됩니다.

## 4. 홈페이지용 피드 (`feed.json`)

피드 생성기(GitHub Actions)가 위 댓글들을 모아 만드는 파일입니다. 홈페이지는 이 파일만 읽습니다.
예시: [`samples/feed.sample.json`](samples/feed.sample.json) — 홈페이지 시안은 이 파일로 개발합니다.

```jsonc
{
  "generated_at": "2026-10-07T12:00:00Z",   // 생성 시각 (UTC, ISO 8601)
  "repo": "moooncang/game",
  "employees": {
    "claude": {
      "name": "Claude",
      "state": "coding",                     // 상태 코드
      "message": "플레이어 이동 스크립트 작성 중",
      "task": 3,                             // 현재 업무 Issue 번호 (없으면 null)
      "updated_at": "2026-10-07T11:58:00Z"
    },
    "gpt": { "...": "같은 구조" }
  },
  "tasks": [                                 // 업무 Issue 목록 (최근 순)
    {
      "number": 3,
      "title": "플레이어 이동 구현",
      "assignee": "claude",                  // 담당 라벨에서 추출 (없으면 null)
      "state": "open",                       // open / closed
      "url": "https://github.com/moooncang/game/issues/3"
    }
  ],
  "reports": [                               // 서류 목록 (최근 순)
    {
      "id": 1234567890,                      // 댓글 ID
      "task": 3,
      "author": "claude",
      "kind": "작업보고",
      "title": "플레이어 이동 구현 완료",
      "pr": 4,                               // 없으면 null
      "body_md": "## 한 일\n- ...",          // 본문 마크다운
      "created_at": "2026-10-07T11:50:00Z",
      "approval": {
        "status": "approved",                // pending / approved / rejected
        "reason": null,                      // 반려 사유
        "at": "2026-10-07T11:55:00Z"
      },
      "url": "https://github.com/moooncang/game/issues/3#issuecomment-1234567890"
    }
  ]
}
```

### 해석 규칙 (피드 생성기 구현 시)
1. 사원 상태 = 모든 Issue를 통틀어 그 사원의 **가장 최근** `office:status` 댓글. 한 번도 없으면 `offline`.
2. 상태 댓글이 **12시간 넘게** 갱신되지 않으면 `offline`으로 간주합니다. (퇴근 보고를 빠뜨린 경우 대비)
3. 결재 댓글(`/승인`, `/반려`)은 **저장소 주인(`moooncang`)이 쓴 것만** 인정합니다. (공개 저장소라 누구나 댓글을 달 수 있음)
4. 상태·서류 댓글도 저장소 주인 계정 또는 등록된 AI 앱 계정이 쓴 것만 인정하는 것이 안전합니다. 허용 계정 목록은 피드 생성기 설정으로 둡니다.
5. 양식이 깨진 댓글(필수 항목 누락)은 버리고, 생성기 로그에 경고만 남깁니다.
